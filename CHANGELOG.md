# Changelog

All notable changes to this project should be documented in this file.

## [Unreleased]

### Added

- Added `tides::angular_speed(name)` (°/h) and `tides::constituent_period(name)` (s): exact constituent speeds derived from each constituent's Doodson argument and the secular rates of the Meeus mean longitudes, so `ω t` advances at the same rate as the equilibrium argument `V₀`. They agree with the tabulated Schureman (1958) speeds to < 10⁻⁷ °/h for all 15 supported constituents, and are now the single source of truth for constituent periods (`TidalConstituent` constructors, `io::constituent_period`).
- **Entropy-stable, well-balanced split-form DGSEM for the 2D SWE (Wintermeyer et al. 2017; REVIEW.md §1.1, §1.6).** New opt-in `SWEFormulation2D` on `SWE2DRhsConfig::with_formulation` (and `SWEPhysics2DBuilder::with_formulation`): `Standard` (default, unchanged), `EntropyConservative`, and `EntropyStable`. The split form replaces the collocated flux derivative with flux differencing along GLL lines using the Wintermeyer two-point flux, adds the collocated bed source `−g h_i Σ_j D_ij B_j` and the interface bed term `½g h⁻(B⁺ − B⁻)·n`, and (`EntropyStable`) Lax–Friedrichs dissipation in entropy variables, `−½λ([[η]], ū[[η]] + h̄[[u]], v̄[[η]] + h̄[[v]])`. Lake-at-rest is exact for **any** nodal bathymetry: smooth of degree ≥ p, cell-averaged, or rough and discontinuous across faces. On the 20 km test the residual is ≤ 4e-12 m²/s² for P1–P4, against 2.5 m²/s² for the collocated scheme at P2. Mass is conserved to ~1e-20. `EntropyConservative` conserves the discrete total energy to round-off (periodic and reflective walls), and `EntropyStable` dissipates it. P2/P3 converge at 3.06/4.00 on a nonlinear manufactured solution with bathymetry. The bed slope is part of the operator, so the RHS panics if `source_terms` also contains `BathymetrySource2D` (new `SourceTerm2D::includes_bathymetry_slope`). Serial and parallel RHS share one element kernel (`solver/rhs/swe_2d_split_form.rs`) and give bitwise-identical output. Fluxes and entropy helpers are in `flux/swe_2d_entropy.rs` (`wintermeyer_flux_2d`, `entropy_stable_dissipation_2d`, `swe_entropy_variables_2d`, …). Wetting/drying is not handled by the split form yet.
- Added a native reader for norkyst-client **grid** parquet (`io/norkyst_parquet.rs`, behind the new off-by-default `parquet` feature → `parquet`/`arrow` 58). Grid extraction runs over OPeNDAP and stays available when the point/NCSS service is down (frequently 503), so it is the reliable path for fetching NorKyst-800 tidal data — but it writes parquet, not text. `read_norkyst_parquet` / `read_norkyst_parquet_glob` decode a file or partitioned dataset into `NorKystGridData`; `sea_surface_height_series_nearest(lon, lat)` picks the wet cell nearest a station and returns its `zeta` `TimeSeries` (and `surface_current_series_nearest` its surface currents). This removes the external DuckDB/Python convert-to-text step: `examples/norkyst_tidal_validation.rs` now reads a `.parquet`/dataset directory directly when built `--features parquet`. Verified end-to-end on a real 2-month Bergen fetch (14 640 grid rows → nearest wet cell → 1 464 hourly `zeta`), reproducing M2 H≈0.427 m / S2 H≈0.117 m, fit R²≈0.97. Shared the exact proleptic-Gregorian time parsing between the text and parquet readers in `io/datetime.rs` (now also accepts RFC3339 numeric offsets `±HH:MM`/`±HHMM`).
- Added `examples/norkyst_tidal_validation.rs` wiring the full P1.5 path end-to-end: NorKyst text file → reader → `HarmonicAnalysis` fit → `reference_constants` (nodal correction removed) → catalogue `(H, G)` comparison. Runs a self-contained synthetic round-trip by default (synthesize a tide from a known catalogue with the forward Schureman correction, write it as NorKyst text, read it back through the real reader, and confirm the inference recovers the catalogue to ~0 RMS) and accepts a real `norkyst-client --format text` file as an argument. Documents the absolute-time → epoch recipe (shift the series to `t = 0`, take `AstronomicalArguments` at the first sample) that `reference_constants` requires.
- Added a NorKyst text-ingest reader (`io/norkyst_reader.rs`, `std`-only, no `netcdf` feature) that parses `norkyst-client --format text` point/site output into `analysis::TimeSeries` for the P1.5 validation path. `NorKystTextData::sea_surface_height_series()` yields the `zeta` series to fit with `HarmonicAnalysis` and compare against catalogue constants; `surface_current_series()` yields shallowest-level `(u, v)` for a first ADCP touchpoint. Times are parsed to exact Unix seconds via a proleptic-Gregorian conversion (chrono `… UTC`, RFC3339 `…Z`, or bare seconds), and `Option<f64>` `Debug` fields (`Some(..)`/`None`/`NaN`) are handled. Companion one-line fix in `norkyst-client` (`print_ocean_data`) so the text format now emits a `surface sea_surface_height=… bottom_depth=…` line — previously the surface elevation was written only to parquet/arrow, so a text reader could not recover tidal elevation. 10 unit tests.
- Added `REVIEW.md`: full-crate code and numerics review (2026-07-08) covering the DG core, 3D/vertical physics, mesh/boundary conditions, performance/GPU, and architecture, with a prioritized fix plan. Supersedes `NUMERICAL_REVIEW.md` and `GPU_EVALUATION.md` (both removed); corrects the allocation conclusion in `PROFILE.md`.
- Rewrote `OUTLINE.md` as a current-state architecture document (module tree, layer status, evolution path) — it previously described the 1D-only crate. Updated the stale architecture tree, key types, and 2D-extension guidance in `CLAUDE.md` to match.
- Added a shared 2D DG diffusion helper for conservative element and face coupling.
- Added regression coverage for tracer diffusion conservation across element jumps.
- Added regression coverage for wet/dry positivity and mass-preservation behavior.
- Added Windows native dependency documentation for HDF5 and netCDF-C setup with Miniforge/conda-forge.
- Added regression tests for the P0 review bugs: depth-dependent vertical-diffusion layer thickness; baroclinic-only vs full PGF; wall zero-normal-flux (`reflect_velocity`); ROMS surface-layer selection in nesting; Greenwich phase-lag sign; and a closed-basin seiche whose period matches the analytic `2L/√(gH)`.
- Added `cosine_filter_is_centred_at_baroclinic_endpoint` regression test proving the mode-split barotropic time filter is centred at `t+dt` (constant tendency reproduces the exact `t+dt` value).
- Added GitHub Actions CI (`.github/workflows/ci.yml`): a check matrix over `--no-default-features` and the `parallel`/`simd` feature combinations (guards TODO P0.10), a `cargo nextest` test job, a `clippy` job (`--lib --tests`), and a `cargo fmt --check` job. The native-HDF5/netCDF default build is left out of CI.
- Added nodal-correction inference to harmonic analysis (`analysis/harmonic.rs`): `ConstituentResult::{remove_nodal_correction, to_reference}` and `HarmonicResult::reference_constants(&epoch)` convert *apparent* constituents fitted from a finite record into nodal-corrected *reference* constants (`H_ref = H_app/f`, `φ_ref = φ_app − (V₀+u)`) at the record's `t = 0` epoch — the exact inverse of `tides::correct_amplitude_phase`, making short-record fits directly comparable to a published catalogue (Kartverket/ROMS). Covered by an end-to-end round-trip test (reference → forward-correct → synthesize → fit → infer → reference) and a pass-through test for unsupported constituents.
- Added `tides` module (`src/tides/`): a from-scratch Doodson/Schureman tidal astronomy layer supplying equilibrium arguments `V₀` and 18.61-year nodal corrections (`f`, `u`) for the standard constituents (M2, S2, N2, K2, K1, O1, P1, Q1, M4, MS4, MN4, M6, Mf, Mm, Ssa). Includes `AstronomicalArguments` (Meeus J2000 mean longitudes s/h/p/N/p₁ and mean lunar time τ), a Gregorian→Julian-Date converter, and `nodal_correction(name, &astro)`. Wired into tidal prediction via `TSTConfig::from_constituent_data_at_epoch`, epoch-aware builders `HarmonicFlather2D::with_nodal_corrections(epoch_jd)` / `HarmonicTidal2D::with_nodal_corrections(epoch_jd)`, the `TidalConstituent::with_nodal_correction` primitive, and the `correct_amplitude_phase` helper. Validated by reference-value tests (mean longitudes at J2000, Meeus Julian-date examples), an internal-consistency test that recovers each constituent's tabulated period from the analytic dV₀/dt, and nodal-factor range checks (M2 0.963–1.038; K1/O1 the 11–19% diurnal modulation).

### Changed

- **One 2D SWE RHS kernel; allocation-free stepping (solver/time/physics, TODO P1.1):**
  - The serial (AoS) and parallel (SoA/SIMD) RHS were two ~300-line copies. Both are now drivers over one per-element kernel (`SWE2DRhsKernel`, SoA kernels with scalar fallbacks without `simd`), so they agree bit for bit, and `compute_rhs_swe_2d_parallel` needs only the `parallel` feature. New `compute_rhs_swe_2d_into` / `compute_rhs_swe_2d_parallel_into` write into a reused output. Element scratch is cached per thread and taken once per rayon job; its buffers carry unused trailing capacity because cached workspaces allocated side by side by different threads shared cache lines (false sharing cost ~25 %). One `boundary_ghost_state` helper serves the standard, split-form and viscous terms (three copies before); the split form uses the new `DGOperators2D::dr_1d_row_major`.
  - Parallel RHS, 16 threads, median: 128² P3 3.55 → 2.3–2.9 ms, 128² P2 2.13 → 1.2–1.3 ms, 64² P5 2.07 → 1.2 ms with `_into` (the allocating wrappers pay ~0.5–1 ms for the fresh output). Serial P5 16.0 → 11.6 ms; P2/P3 serial unchanged.
  - API (time, breaking for external integrators): `TimeIntegrator::step_with_workspace(state, dt, t, rhs_into, stage_hook, &mut StageWorkspace)` is now the one required method; `step` and `step_with_stage_hook` are provided on top of it (same results). `Integrable::copy_from` (defaults to `clone_from`), and `SystemSolution`/`SystemSolution2D` implement `clone_from` without reallocating.
  - `PhysicsModule::compute_rhs_into` (default: delegates to `compute_rhs`). `SWEPhysics2D` implements it with the parallel kernel and uses the parallel `compute_dt` when `parallel` is enabled. `Simulation` keeps a `StageWorkspace` per run: a warm step allocates nothing (new `tests/allocation_test.rs` with a counting allocator; the previous path allocated 1.3 MB per step on its 24² P3 mesh). The allocation test is compiled out with `mimalloc`.
  - Tests: serial-vs-parallel RHS is now compared bitwise and covers walls, nodal bathymetry, trait sources and the split form; `_into` with a stale output buffer; output-size check.
- API (time): `step_with_stage_hook` is now a required method of `TimeIntegrator`, and `step` is a provided method that calls it with a no-op hook. It was previously an inherent method of `SSPRK3` only; `ForwardEuler` and `StandardIntegrator` implement it too. External `TimeIntegrator` implementations must implement `step_with_stage_hook` instead of `step`. `SSPRK3`'s stage logic now exists once instead of twice.
- CI: the test job is now a matrix over the same four feature sets as `check` (no-default-features, parallel+simd, parallel-only, simd-only). `cargo check` skips test code, so feature-gated test code could break without CI noticing.
- CI: builds with `RUSTFLAGS="-C target-cpu=x86-64"`, overriding the `-C target-cpu=native` in `.cargo/config.toml`. Hosted runners differ in CPU and `Swatinem/rust-cache` does not key on `.cargo/config.toml`, so a restored cache could contain proc-macro dylibs built for another CPU; rustc then crashed with `SIGILL` when loading them, failing PR checks at random. RUSTFLAGS is part of the rust-cache key, so the old caches are not reused. Local builds keep `target-cpu=native`.
- API (boundary, breaking): `Radiation2D` is now referenced to a surface elevation instead of an external depth. `Radiation2D::new(h_external)` and `Radiation2D::with_velocity(h_external, u)` are replaced by `Radiation2D::still_water()` (also `Default`), `Radiation2D::with_elevation(eta_ext)` and the builder `.with_external_velocity((u, v))`; the `h_external` field is now `eta_external`. The old constructors were removed rather than reinterpreted so existing calls fail to compile instead of silently meaning η = h. For a flat bed at `B = −h0`, `new(h0)` becomes `still_water()`. Added a P1.4 TODO item to replace the per-type open BCs with one characteristic OBC.
- API (3D, breaking): the sigma-coordinate vertical velocity Ω is now stored at the **w-points** — `compute_vertical_velocity` fills `n_elements·n_nodes·(n_levels + 1)` values (bed … surface interface per column) and `compute_rhs_3d` / `apply_vertical_advection_3d` / `apply_vertical_tracer_advection_field` expect that layout. `apply_vertical_advection_field` now takes `(rhs, field, state, bathymetry, w_vel, sigma)` like the tracer variant. `Hydrostatic3D::post_process` averages Ω to layer centres for the `Solution3D::w` output field.
- Replaced `REVIEW.md` with the 2026-09-25 full-crate code and numerics review, which supersedes the 2026-07-08 review (still in git history). Its headline findings:
  - Realistic nodal bathymetry is not well-balanced (measured: 0.9 m/s spurious currents after 1 h at P3 over a 30→400 m slope).
  - Hydrostatic reconstruction leaks mass when bathymetry is face-discontinuous (measured).
  - Flather-type open boundaries apply the characteristic relation twice (reflection ≈ −1/3).
  - Tidal constituent periods are truncated.
  - Mode splitting is first-order and damped; the G-term double-counts advection; 3D stresses never reach the depth mean.
  - 3D tracers are not constancy-preserving; vertical momentum advection is D times too large; the σ pressure-gradient error is comparable to the physical forcing.
  - The review also includes a cost model versus ROMS for 2D tides (~47× core-hours as configured).

### Fixed

- **3D tracer flux through coastal walls (3D, TODO P0.22):** at physical boundaries `apply_tracer_advection_3d` used the interior velocity (transmissive) and the tracer BC's exterior value, so heat and salt crossed the coastline while the volume flux Ω and momentum treated it as a wall (P0.7). The ghost state is now the reflected velocity with the interior tracer and layer thickness, which makes the Rusanov tracer flux exactly zero, like the volume flux. Reflecting the velocity alone would not suffice: a ghost value from `FixedTracerBC3D`/`UpwindTracerBC3D` still leaks through the dissipation term. As a consequence `TracerBoundaryCondition3D` (`Hydrostatic3D::temp_bc/salt_bc`) is not consulted until the 3D layer gets open boundaries with a volume flux; this is documented on the trait. Regression test `horizontal_tracer_advection_closed_basin_conserves_inventory`: flow into the walls of a closed basin with a sloping bed, for the extrapolation, fixed and upwind BCs; the inventory tendency was −0.39 of the advective scale and is now < 1e-12 of it.
- **Limiter plumbing (solver, TODO P0.19):**
  - The parallel fused Kuzmin + positivity limiter (`apply_swe_limiters_kuzmin_2d_parallel`, the production path of the legacy `ssp_rk3_swe_2d` stepper under `parallel`) had no dry-element branch. With a mean depth below `h_min`, θ clamped to 0, so dry elements kept their mean momentum and a negative mean depth survived; serial and parallel runs diverged. Serial and parallel limiters now run the same per-element kernels, so they agree bitwise, and the parallel versions work in place instead of copying every field and every element (`to_vec`, per-element `Vec`s, serial copy-back). The serial `apply_swe_limiters_kuzmin_2d` is now a single fused pass too. `StandardLimiter2D` (used by `SWEPhysics2D`) runs the fused kernel for `KuzminWithPositivity` and uses the parallel versions when `parallel` is enabled.
  - The `Simulation` runner applied `PhysicsModule::post_process` (limiters, wet/dry correction) once per step, so the second and third SSP-RK3 stages evaluated the RHS on unlimited states, voiding the Zhang–Shu positivity guarantee. It now runs after every stage.
  - Regression tests: dry elements (with momentum and with a negative mean) and a negative node under the serial and parallel fused limiters; serial-vs-parallel bitwise equality for all three limiter pairs; and a `Simulation` test in which the RHS drains the depth, asserting that no RHS evaluation sees h < 0 and that `post_process` runs 3× per SSP-RK3 step.
- **2D SWE time step (solver, TODO P0.21):** `compute_dt_swe_2d` paired the global minimum element size 2√detJ with the global maximum wave speed |u| + c. On graded meshes this is several times too small: a small element in shallow water limited by the celerity of the deepest water (≈ 3.8× too small in the new regression test, up to ~11× on fjord meshes per REVIEW.md §5.3). √detJ also overestimates the size of long, narrow elements, a stability risk. Each node now pairs its own wave speeds with its element's metric, Δt = CFL/(2N+1)·min 4/(λ_r + λ_s), with λ_r = |u·∇r| + c|∇r| (the tensor-product sum used by Trixi.jl). On square elements at rest this is the old CFL·Δx/((2N+1)c), so CFL numbers keep their meaning. The serial and parallel versions share one per-element kernel and agree bitwise. New `positivity_cfl_swe_2d(N)` (`const fn`) gives the DGSEM Zhang–Shu bound for SSP-RK3 in these units, (2N+1)/(2N(N+1)) = 0.75/0.42/0.29/0.23 for N = 1–4, now valid for any element shape. `examples/froya_real_data.rs` runs at that bound (5/12 at P2) instead of CFL 0.1. Regression tests: analytic dt on squares (at rest and with flow), on a graded anisotropic two-element mesh, serial vs parallel, the positivity values, and a dry domain.
- **`Bathymetry2D::linearize` documentation (TODO P0.14):** the doc said planar bathymetry is "CRITICAL for well-balanced schemes" and that the pressure gradient and source cancel for linear B. With the collocated scheme that holds only for p ≥ 2: at p = 1 the linear interpolant of ½gh² leaves a residual g(h̄ − hᵢ)∂B. The doc now states this, notes that the per-element fit jumps across faces (needs `with_well_balanced(true)`), and points to `SWEFormulation2D::EntropyStable`, which is balanced for any nodal B. Regression test `test_lake_at_rest_linearized_bathymetry` (p = 1 not balanced; p = 2, 3 and the split form balanced to round-off).
- **Test build without `simd` (tests):** `cargo test --no-default-features --features parallel` did not compile. `test_batched_matches_scalar` (`solver/simd/batched.rs`) imported the `simd`-only `apply_diff_matrix`; it now compares against the always-available reference `apply_diff_matrix_scalar`, which the SIMD kernel falls back to at this order anyway. `test_viscosity_parallel_consistency` was gated on `parallel` alone but uses `compute_rhs_swe_2d_parallel`, which is exported only with `parallel` and `simd`; its gate now matches. The examples `profile_cpu`, `high_res_benchmark` and `quick_profile` had the same `parallel`-only gates around `compute_dt_swe_2d_parallel`/`compute_rhs_swe_2d_parallel` and failed to build under `parallel` alone (`cargo test`/nextest build examples); their gates now match too. All test targets and examples build, and the tests pass, under all four feature sets.
- **`Radiation2D` open boundary (boundary):** the ghost was the interior state whenever `u_n + c > 0`, i.e. for every subcritical flow, so the boundary was zero-gradient extrapolation: the incoming Riemann invariant came from the interior and nothing held the far-field level. In the quasi-1D channel test an outgoing pulse reflected 10.2 % of its amplitude and the channel then grew to 51× the pulse amplitude by 200 s. The ghost is now the external state (`h = η_ext − B`, `u_n = u_n,ext`, `u_t` from the interior), as for `Flather2D`, which also makes it bathymetry-aware (REVIEW.md §4.6): reflection is now 1e-6 and the channel stays at 1.8e-6 of the pulse amplitude through 200 s. New regression tests `radiation2d_outgoing_pulse_does_not_reflect`, `radiation2d_stays_quiet_after_pulse_exits` and `flather2d_stays_quiet_after_pulse_exits` (a long-run check carried over from the superseded PR #7), plus unit tests for lake-at-rest over any bed, the η-referenced ghost depth, no interior extrapolation, and the velocity decomposition.
- **Tidal constituent periods (tides/analysis):** `TidalConstituent::{m2, k1, o1, n2, p1}` hard-coded two-decimal periods (M2 12.42 h, K1 23.93 h, O1 25.82 h, N2 12.66 h, P1 24.07 h). Every harmonic fit (`HarmonicAnalysis::standard()`/`norwegian_coast()`) and harmonic BC built on them accumulated phase error over the record. Measured on a synthetic tide at the true speeds (fitted − true phase): 60-day `norwegian_coast()` fit M2 −1.1°, N2 +3.2°, K1 −1.5°, P1 −3.5° (K1/P1 amplitudes 3–6 % low); 1-year `standard()` fit M2 −6.2°, K1 −12.3°. The existing round-trip tests synthesised with the same truncated periods and could not see it. The constructors now use the exact Doodson periods. `io::constituent_period` delegates to the same source, which also corrects its long-period entries (Mf −3.4 s, Mm −7.1 s, Ssa +3.8 s). Regression tests fit a tide synthesised at the tabulated speeds (60-day Norwegian-coast set, 1-year standard set; phase error < 0.1°) and check each constructor's speed.
- **3D vertical momentum advection (3D):** `apply_vertical_advection_field` divided the vertical flux difference `δ(Ω u)` by `Δσ`, but Ω from `compute_vertical_velocity` is a volume flux per unit area in m/s (it integrates `∇·(D u)·dσ`). The tendency was therefore `D` times too large (200× in a 200 m column). It now divides by the layer thickness `Hz = D·Δσ`, as the tracer path already did. Ω was also averaged to layer centres and re-averaged to interfaces by the advection kernels, which smeared it across neighbouring layers and broke discrete layer continuity `∂ₜHz + ∇·(Hz u) + δΩ = 0`; it is now kept at the interfaces (see *Changed*). Regression tests: analytic `−(1/Hz)δ(Ωu)` for linear Ω(σ), u(σ) in a D = 200 m column, and per-layer continuity of Ω for a zero-mean shear flow.
- **UNESCO EOS pressure units (equations):** `EquationOfState::density` takes pressure in dbar but passed it straight into the UNESCO (Millero & Poisson 1981) secant bulk modulus, which is fitted in bar, so seawater was 10× too compressible (ρ(5 °C, 35, 1000 dbar) ≈ 1069.5 instead of ≈ 1032.3 kg/m³). Pressure is now converted to bar. Regression test against the eight UNESCO check values (e.g. ρ(35, 25 °C, 1000 bar) = 1062.53817, ρ(35, 5 °C, 0) = 1027.67547).
- **Chezy friction (source):** `ChezyFriction2D` and the 1D `ChezyFriction` returned `S_hu = −c_d |u| u / h` with a documented-dimensionless drag coefficient `c_d`. The depth-integrated quadratic-drag source is `−c_d |u| u` (m²/s²; bed stress `τ_b = ρ c_d |u| u`), so the extra `1/h` made friction depth-dependent and wrong in magnitude (2× too strong at 0.5 m, 50× too weak at 50 m). It is removed. Regression tests check the magnitude at several depths and that Chezy with `c_d = g n²/h^{1/3}` equals Manning at that depth.
- **Flather-type open boundaries no longer reflect outgoing waves.** `Flather2D`, `HarmonicFlather2D`, `ChapmanFlather2D`, `TSTOBC2D`, `NestingBC2D`, `OceanNestingBC2D` and the 1D `FlatherBC` built their ghost normal velocity as `u_n,ext + sqrt(g/h)(η_int − η_ext)` and then handed it to the upwind Riemann solver, which applies the characteristic (Flather) relation itself. The correction was counted twice: outgoing waves reflected with coefficient −1/3 (−0.29 at the 0.8 nesting weight used by `examples/froya_real_data.rs`; −0.20 for `ChapmanFlather2D` defaults with a matching `h_ref`, −0.57 in 100 m water; −0.43 for `TSTOBC2D` with its extra "subtidal" radiation velocity), and a progressive wave forced with a consistent external velocity arrived as a standing pattern of 0.67–1.45× the prescribed amplitude. The ghost is now the external state (`h = η_ext − B`, `u_n = u_n,ext`, `u_t` from the interior or external data), and the Riemann solver takes the outgoing invariant from the interior and the incoming one from outside. New `tests/open_boundary_flather_test.rs` (quasi-1D channel, SSP-RK3): outgoing-pulse reflection is now < 1e-5 for every Flather-type BC (was 20–43%), and a forced progressive wave is delivered at 0.997–1.001× its amplitude (was 0.67–1.45×). Unit tests that encoded the old ghost velocity now check the ghost state plus an outward Riemann mass flux; a new unit test checks the Roe boundary flux reproduces the Flather relation exactly once.
  - Behaviour note: with zero external velocity (the default of the elevation-only BCs) the incoming invariant is `−sqrt(g/h) η_ext`. That delivers η_ext at a boundary sitting at an antinode of a standing tide (small coastal domains), but a *progressive* wave arrives at η_ext / 2 (it was 2/3 with the double-counted ghost). Supply the external normal velocity (`ChapmanFlather2D`, nesting BCs) to force a progressive tide.
- **`Chapman2D` default without a time step (boundary):** with no `dt` on the BC or in `BCContext2D` the radiation coefficient fell back to `c·dt/dx = 1` (α = 1/2), and nothing in the library sets `BCContext2D::dt` (`SWE2DRhsConfig::with_dt` has no callers). In the weak DG setting that blend feeds the interior's incoming Riemann invariant back into the ghost and is unstable for α ≲ 0.7: a single pulse blew up within ~75 s in the channel test. The fallback is now α = 1 (the dt → 0 limit, a stable elevation clamp). New regression test `chapman2d_without_dt_stays_bounded`. `Chapman2D` itself is not a Flather BC and is unchanged otherwise, but it is documented as what it is in DG: a softened elevation clamp that reflects outgoing waves (~99% for α ≳ 0.8). Use `Flather2D`/`ChapmanFlather2D` for radiating boundaries.
- **2D SWE mass conservation with hydrostatic reconstruction (REVIEW.md §1.3):** with `with_well_balanced(true)` and bathymetry that jumps across faces (`Bathymetry2D::to_cell_average`/`linearize`, as in `examples/froya_real_data.rs`), the strong-form surface term evaluated the interior flux on the *reconstructed* state, so it no longer telescoped with the volume term and each element's mass rate picked up `−∮(h⁻ − h*⁻)u⁻·n`. On a 12×12 periodic 20 km domain with a slope-correlated flow this leaked −5.2e-5 of the total mass per second; it is now ~1e-20 (p = 1, 2, 3). The interior flux is now `F(q⁻)` of the nodal state, and well-balancing enters as the Audusse momentum correction `½g(h*⁻² − h⁻²)·n` (new `HydrostaticReconstruction2D::pressure_correction`), identically in the serial and parallel RHS. Lake-at-rest over cell-averaged B stays at round-off. Regression tests: `test_mass_conservation_hydrostatic_reconstruction_discontinuous_bathymetry`, `test_lake_at_rest_cell_averaged_bathymetry` (serial + parallel), and `test_parallel_matches_serial` now also covers bathymetry with reconstruction.
- **Docs (REVIEW.md §1.2):** `SWE2DRhsConfig::well_balanced`/`with_well_balanced` no longer tell users to leave out `BathymetrySource2D`. That advice holds only for cell-constant bathymetry; for nodal bathymetry dropping the source leaves an unbalanced `g h ∂B/∂x` in the volume term (≈0.6 m/s² lake-at-rest accelerations).
- **Tide-gauge times (io):** `read_tide_gauge_file` converted ISO timestamps with 365-day years and 30-day months, putting e.g. 2024-06-01 about 13 days away from the NorKyst readers' value, so gauge and model series compared on absolute time were misaligned by days. It now uses the shared exact proleptic-Gregorian parser (`io/datetime.rs`).
- **NorKyst ingest (io):** a `site_id:` line now applies to every following `time=` block (as the documented format shows), not just the next one. Text-path series are time-sorted and one sample per timestamp; the parquet series de-duplicate repeated cell/time rows from overlapping selections or re-fetched months (previously a zero time step fed the harmonic fit). `surface_current_series_nearest` picks its cell by current availability, so pre-zeta datasets yield currents and a zeta gap at the nearest cell no longer moves currents to a farther one. The parquet `time` column may now be LargeUtf8, Utf8View or dictionary-encoded (polars/DuckDB rewrites); null times are an error. The datetime parser rejects out-of-range fields (`2024-02-30`, `25:61`, tz `+24:00`) and non-finite numbers instead of rolling them over or returning NaN.
- **1D SWE surface-term sign and mass conservation with hydrostatic reconstruction:** `compute_rhs_swe` lifted `F* − F⁻·n`, the opposite of the strong-form `F⁻·n − F*` used by the 1D advection and 2D SWE kernels. Each element's rate was then `2(F₀ − F_N) + F*_R − F*_L`, so mass and momentum were conserved only while the state stayed continuous across interfaces, and the upwind term was anti-dissipative: a smooth periodic wave on a flat bottom blew up (|q| ≈ 1e8) within 0.2–0.5 s for p = 1–3. Nothing in the crate time-stepped this RHS, so the bug was latent. Separately, with `well_balanced` (the 1D default) the interior flux was evaluated on the Audusse *reconstructed* state, adding `−(h⁻ − h*⁻)u⁻·n` to each element's mass rate wherever B jumps across an interface. The surface term is now `F(q⁻)·n − F*(q*⁻, q*⁺) + ½g(h*⁻² − h⁻²)·n`: nodal-state interior flux, numerical flux on the reconstructed states, and the Audusse momentum correction (new `HydrostaticReconstruction::pressure_correction`, pressure taken as zero for `h ≤ h_min`), the 1D analogue of the 2D `HydrostaticReconstruction2D::pressure_correction` fix. On a periodic 20 km domain with cell-averaged B = −200 + 150·sin(2πx/L) and a slope-correlated flow, the mass rate went from −1.1e-4 of the total mass per second to ~1e-20 (p = 1–4; Roe, HLL and Lax–Friedrichs). Lake-at-rest over the cell-averaged bed stays at round-off. Regression tests: `test_conservation_discontinuous_state_flat_bottom`, `test_mass_conservation_hydrostatic_reconstruction_discontinuous_bathymetry`, `test_lake_at_rest_cell_averaged_bathymetry`, `test_pressure_correction_balances_lake_at_rest`, and new manufactured-solution convergence tests `test_convergence_swe_1d_p{1,2,3}` (observed orders 2.1 / 3.0 / 4.0 for all three fluxes; all went to NaN before the fix).
